# NAS 下载管理：v3.65.0-bitqiu.15

本版在现有 NAS 下载、断点续传与最多 5 个并发任务基础上增加以下功能，不更改下载目录、最终文件名或官方 AList 登录流程。

## 文件类型图标

独立 NAS 页的文件选择、本地目录、进行中及历史任务统一使用本地内嵌 SVG。文件夹以真实目录属性识别；文件按扩展名区分视频、音频、图片、文档、压缩包、代码及通用文件。不依赖字体方块、外部 CDN、缩略图或远程请求。扩展名只用于视觉分类，不作为文件内容或安全判断。官方 AList 文件页已有自己的类型图标，继续使用官方前端。

## 同名文件预检查

点击下载先在后台递归检查，不启动传输；发现同名文件，弹窗显示路径、双方大小和修改时间，提供替换、跳过、取消本次下载。可勾选“将此选择用于本次下载的其余冲突”，仅作用于这一次提交，下一次不会默认替换。跳过会在历史中标明“已跳过”。

同名普通文件夹合并检查内部文件，不删除整个目录。符号链接、设备及文件/目录类型不匹配不能套用替换规则；目标父路径类型异常需更换保存目录。已有进行中、暂停或失败的相同目标任务仍提示操作原任务，防止两个任务写同一路径。

预检查方案由后台关联管理员账号保存，15 分钟后过期，只能提交一次；限制最多 16 个方案、合计 200000 条任务。权限、路径及目标状态在提交和传输阶段重新核对。替换先写同目录临时文件，完整接收和同步后使用文件系统原子重命名；下载失败保留旧文件。确认后目标元数据发生变化会停止替换，要求重新检查。NAS 上其他程序不受本应用锁控制，确认期间应避免同时编辑同一个目标文件。

新增管理员接口：`POST /api/admin/bitqiu/nas/prepare`、`POST /commit`。原 `/download` 保持原有“不覆盖”行为，不能通过旧 overwrite 参数绕过确认。

## 文件夹任务

新提交的顶层文件夹显示一个汇总任务，默认收起；点击文件夹名称/箭头展开内部文件，继续显示每个文件的状态、进度和操作。定时刷新保留当前页面的展开状态；刷新整个页面默认收起。进度按需下载文件的字节加权，跳过文件不计入下载容量；未知大小显示“总大小未知”，同时展示完成文件数。部分失败/部分取消明确标注，不能显示为全部正常结束。

文件夹和子项勾选联动；父项控制展开为去重后的子任务操作，暂停整个文件夹会先冻结其等待子任务；原单文件/不完整选中项的暂停规则保留。父项不占并发名额，子文件仍由原复制引擎和 NAS 上限调度。任务计数和历史分页按顶层文件夹/单文件展示，展开内部文件不会占用额外历史页。老任务没有分组标识，继续以原单条方式展示，不猜测其归属。

## 历史记录

- 支持单条、清理选中历史、清空历史，均弹窗确认。
- 只删除历史记录，不删除 NAS 上的最终文件。失败记录删除后不能再从该记录续传。
- 可另行勾选删除这些任务的断点临时文件，默认不勾选；这不是删除最终文件。
- 文件夹按整组清理。任何子任务仍在等待、下载、暂停或停止处理中，则整组跳过。
- 后台启动时及每天执行自动清理，以结束时间计算，整组全部结束超过 90 天才清除。关闭网页仍执行；自动清理保留临时文件。
- 保留下来的临时文件为 `.文件名.alist-bitqiu-任务ID.part`，记录清除后需自行管理。自动清理不会为了删除记录而默默删除 NAS 数据。
- 批量清理先持久化一次，写入失败恢复内存记录；成功后释放原引擎中的对应历史项。手动临时文件清理失败会显示失败数量。

新增管理员接口：`POST /api/admin/bitqiu/nas/history/clear`，`scope=all|selected`、`ids`、`confirmed=true`，以及默认 false 的 `remove_partials`。跳过仍有活动任务的组，并返回 deleted/skipped/partial_failures 数量（内部任务记录数）。

## 数据与部署兼容

继续使用现有 `task_items / bitqiu_nas_v1` JSON 记录，增加可选分组、批次和替换确认字段，无数据库结构迁移、新环境变量或额外宿主机目录。继续挂载原 `/opt/alist/data` 和 `/downloads`，保留原数据升级。原 API 字段保留，新接口均受原管理员鉴权保护；物理目录、源会话和替换校验值不下发任务列表。

不建议在新任务传输期间降级。旧版本无法执行新的替换确认语义或显示新分组/跳过状态；回退前先暂停新任务并备份数据库和临时文件。


## v3.65.0-bitqiu.16：增量目录与目录选择

新增 `POST /api/admin/bitqiu/nas/list-stream`，请求 `{path,refresh}`，响应为逐行 JSON：start、batch/content、done/total 或 error/message。每批经权限、隐藏规则及同名去重后输出；缓存命中及不支持增量的兼容驱动仍使用完整结果分批输出。BitQiu Windows 与网页模式均支持接口分页回调。普通目录 API 保持原行为，不返回部分成功；流式回调仅用于观察进度，失败/取消不会将部分目录放入缓存。回调请求不通过普通 singleflight 共享响应对象。

前端用 fetch 流读取 UTF-8，必须收到匹配实际条目数的 done 并正常结束才认定完整。目录流中断、后续页失败及异常数据保留已读条目但显著标记未完成，禁用全选和下载。切换目录取消旧请求并隔离迟到结果。目录排序在浏览器对已读条目执行，加载中位置可能随新条目调整；完成时覆盖全部直接条目。无目录页数和每页数量控件，历史任务分页保留。

新增 `POST /api/admin/bitqiu/nas/entries`，返回右侧本地目录中的全部对象和可选择标记，普通文件/链接禁选。原 `/dirs` 保持仅目录格式。右侧路径右方的多选分类使用与图标相同的扩展名分类；重置为全选，不改保存路径、不删文件。旧网页/客户端继续使用原 API，无数据迁移。代理若强制缓冲响应，首批显示可能被延迟，应关闭该接口的代理缓冲；Nginx 可识别服务器的 `X-Accel-Buffering: no`。

## iOS 内置浏览器与登录状态

NAS 页面与 AList 主页面复用同一浏览器存储中的 `token` 和 `alist_client_id`，普通 API、目录流式请求及入口身份检查都携带 `Client-Id`，避免被设备会话管理识别成另一台设备。不会新建设备标识或放宽管理员权限。

登录失效、设备会话失效、活跃设备达到上限与缺少管理员角色分别显示原因。浏览器不允许网站存储或切换页面后无法读取登录状态时，页面提供重新登录及 Safari 访问提示；不同浏览器或极空间 App 的独立浏览器窗口之间不会自动共享登录。请在实际打开 NAS 页面的浏览器中登录 AList 管理员，BitQiu 云盘账号本身不授予 AList 管理员权限。

兼容性验证包含 Chromium 与 WebKit 的根路径/前缀路径、设备标识传递和错误分类；极空间 iOS App 实机仍需用户验证。
