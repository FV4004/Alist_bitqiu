# Bitqiu / NAS 盘点与人工复核预发布

本版在功能分支开发，不合并 main。测试平台沿用仓库支持的 Linux amd64；其他架构尚未提供构建和验收。测试入口为 `/@nas`，支持现有 AList 访问前缀。

## 本次新增：按大小筛选（v3.65.0-bitqiu.22-size-filter-preview）

NAS 下载页面的“文件分类”下方新增大小范围筛选，拖动条和手动输入同一行、各占一半；窄屏仅将右侧两个输入框上下排列，保持左右等宽。默认最小值 80 MB、最大值留空不限。任一边留空即该方向不限，双方留空不限制大小；零是有效数值，不当作留空。

与现有文件大小显示保持一致，沿用 1024 进制（界面标为 MB，1 MB = 1,048,576 字节），包含范围上下界。拖动条采用非线性刻度，末端表示最大值不限；手填大于当前刻度时会扩展刻度，支持最多 6 位小数。负数、非法数值或最小值大于最大值会提示错误，并保留上一有效筛选结果。

可分别应用到网盘/NAS，与名称搜索、类型筛选取交集。只过滤已加载的当前目录，不增加目录 API 请求。文件夹不按大小排除，方便继续浏览；大小未知的文件在启用任一范围限制时不匹配，并显示数量提示。清空范围后未知大小文件恢复显示。

筛选不会取消已勾选项目，不改变下载选择或后台扫描范围。目录缓存保存原始清单，返回目录时使用当前大小范围，不恢复旧筛选条件。该功能不新增数据库字段，回退沿用下述方案。

## 安装与回退

1. 下载本 Release 的二进制包或离线 Docker 镜像、`SHA256SUMS`、`COMMIT` 和本说明。在相同目录运行 `sha256sum -c SHA256SUMS`。
2. 停止旧容器，备份整个 `/opt/alist/data`，包括 SQLite 数据库及其 WAL/SHM 文件（停止后复制）。保留旧镜像与原容器配置。禁止两个进程同时写同一数据目录。
3. `gzip -dc alist-bitqiu-inventory-linux-amd64-image.tar.gz | docker load`，使用导入的 `alist-bitqiu:inventory-<提交前12位>` 镜像新建测试容器。也可在 NAS Docker 图形界面导入 gzip 镜像；仅支持 tar 的界面先解压。
4. 沿用原数据挂载、网络和端口；将 NAS 文件夹挂载至 `/downloads`，在 AList 配置为本地存储。只读盘点可使用已有的只读本地存储；补缺下载需要目标可写，默认 `/downloads` 入口检查仍要求读写挂载。
5. 二进制安装：解压 binary 包，在停止服务后替换原 `alist`，保留配置与数据目录。此构建为包含 SQLite 的静态 Linux amd64 二进制。
6. 回退：停止测试容器/服务，恢复旧镜像/二进制和原配置。如需完整回到测试前状态，恢复停机备份。回退不会撤销已下载的文件；清理这些文件需管理员另行人工处理。

## 持久化与兼容

复用现有 `task_items` 的 `bitqiu_nas_scans_v1` JSON 日志，以可选字段增加双端对象、证据、复核事件和最近不完整尝试。不新增表、不修改旧下载队列记录，无 DDL 迁移。第一次新盘点写入扩展字段；老扫描缓存仍可读，在界面按原流程显示，不伪造复核证据。新版盘点补缺仅允许当前证据下人工确认缺失且逐项明确选中的项目，目录选择不隐式确认后代。

旧版 Go JSON 解码忽略新增字段，可读取旧字段；但旧版重新保存扫描日志会丢失新字段。因此回退前必须备份新版数据，重新升级后旧版改写的缓存需重新盘点和复核。不降级重写数据库格式；原下载暂停/恢复/取消与并发控制继续复用原模块。

每个用户的来源根目录、目标根目录、排序后的选中顶层名称及盘点选项共同构成范围身份。同范围保留最近完整结果；本次失败、取消、超时或重启中断不会用不完整数据覆盖完整缓存。扫描范围最多保留 12 份；每次至多 50000 项、128 层、30 分钟，名称候选比较上限 400 万次。超过上限失败并保留原完整结果，不截断后误判。每个条目最多保留 100 个复核事件；超过后需重新盘点并按保留策略管理旧记录。复核事件含用户、时间、备注、候选与当时证据，不保存密码、令牌、驱动配置或签名下载地址。

## 功能与证据规则

- 六个界面：范围设置、双端盘点、差异匹配、人工复核、报告导出、补缺下载。统计文件/目录、类型、已知容量、未知大小和 NAS 完整 SHA-256 重复候选；不移动、重命名或删除文件。
- 相对路径保持目录映射。NAS 盘点范围为右侧所选目标目录及其全部后代，来源范围为左侧明确勾选的文件/文件夹。选择单个来源文件时，仍盘点所选 NAS 目录，避免漏掉同级改名或子目录内移动的候选。跨目录选项仅允许在该 NAS 目录内跨层寻找候选，不越过所选 NAS 根目录。NAS 独有仅表示未出现在本次所选来源清单中，不代表其他未选网盘范围也没有此文件。
- 同路径大小不同单列；未知大小不作为零；路径和已知大小一致仍标为内容未校验。候选包含完整元数据和证据，同名或名称相似不证明内容相同，多个候选全部保留。
- Bitqiu 的 `fileMd5` 字段会检查十六进制格式及长度并记录，但尚未验证真实服务的完整内容语义；不将其当作已验证完整 MD5。默认不请求下载链接。按需完整读取 NAS 计算 MD5/SHA-256；当前真实 Bitqiu 来源仍可能只能给出“内容未校验”。
- 来源分页失败、权限错误、NAS 读取失败、链接、类型冲突和扫描期间可观察到的元数据变化标记无法判断/扫描问题。并发修改无法提供原子文件系统快照；扫描后修改仍需预检查及实际写入防护。
- 不完整尝试的扫描问题单列；如果没有完整缓存，可查看/导出该尝试，但禁止复核和补缺。已有完整缓存时继续展示缓存并提示最新扫描未完成；最新扫描非完整完成时禁止用缓存补缺。
- 复核支持确认缺失、关联具体候选、忽略、待处理、备注和撤销。批量操作最多 1000 项，仅限明确勾选项目，并再次确认作用范围。证据指纹变化后旧结论标记需重新确认，阻止补缺。
- CSV 和 JSON 可选择疑似缺失、已确认缺失、待复核、其他差异及扫描问题。包含范围、时间、元数据、匹配依据、复核人和备注。JSON 还含完整双端盘点清单；CSV 防止表格公式注入。
- 补缺仅处理人工确认缺失且明确勾选的条目；生成清单和最终确认时复查来源、权限、挂载、当前复核结论、NAS 目标与已有任务。跳过项显示原因，最后再次人工确认才入队。补缺不设置替换标志，复用现有排他创建、防覆盖与队列并发控制。

## 发布隔离

新增工作流只在 `nas-management-inventory-review` 分支运行，测试通过后构建本地镜像、导出离线文件并创建 GitHub Pre-release，`make_latest` 为 false。无 registry 登录、镜像推送或生产部署步骤，只有 `contents: write` 权限。

生产工作流增加 job 级 `refs/heads/main` 限制，阻止预发布标签误触发生产发布。新预发布标签使用 `nas-inventory-preview-<提交前12位>`，也不匹配旧生产标签模式。回退工作流只监听其原分支，本版不会触发。

## 验证边界与待实机验收

GitHub Actions 运行记录对应本 Release 的精确提交；通过才发布安装包。验证涵盖后端 race、盘点匹配/证据/复核、旧下载与队列回归、Node 界面测试，以及 Chromium/WebKit 的根路径和前缀访问。浏览器 API 为确定性模拟，NAS 后端使用临时本地目录，不等于真实 Bitqiu/NAS 验收。

以下必须在真实环境验收：Bitqiu MD5 是否完整内容哈希及缺失比例、真实分页与节流、实际网盘权限失效、NAS 挂载与文件系统语义、真实大目录/大文件性能、NAS App 内登录交接、实际网络中断后的下载恢复、不同 NAS 大小写规则、容器升级和备份回退。未在本次环境实机验证，不宣称已通过。
