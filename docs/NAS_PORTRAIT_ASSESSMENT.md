# NAS 下载页竖屏适配可行性评估

评估日期：2026-10-16。范围仅为可行性和现有行为检查，本次不实施竖屏布局改版。

## 结论

可行。现有页面为独立 HTML/CSS/JavaScript，已声明 viewport，并在 850px 以下把文件选择和目标目录切换为单列；任务卡片在窄屏将操作按钮移到下一行。无需修改网盘协议、下载队列或 Docker 部署即可进一步优化手机竖屏交互。

## 现状验证

使用 Chromium 模拟 320、360、390、430、768 CSS 像素宽、844px 高的竖屏窗口，分别测试根路径和 `/alist` 前缀。包含并发选择器、文件勾选、目标目录、任务控制和历史任务的页面均无横向溢出。并发设置、刷新恢复、操作失败回滚等现有交互通过自动测试。

| 宽度 | 横向溢出 | 测试样例的页面总高度 |
| --- | --- | --- |
| 320px | 无 | 4704px |
| 360px | 无 | 4427px |
| 390px | 无 | 4187px |
| 430px | 无 | 4163px |
| 768px | 无 | 4012px |

这些高度来自确定的测试文件及历史任务数量，不代表真实网盘的固定页面长度。测试为浏览器视口模拟，未在实体 iPhone/Android 或极空间内嵌浏览器上验收。

## 值得改进的地方

- 触控目标：当前最小按钮约 22px 高，复选框为 17px 宽。建议扩大实际可点击区域至约 44px，保留清晰的全选/半选状态。
- 页面长度：文件、目标目录和任务上下排列后滚动较多。可评估折叠目标目录、分步骤选择或独立任务标签页；应保留选择状态，避免误下载。
- 操作可达性：选择容量及下载按钮可考虑底部固定操作区，需要处理浏览器底栏、软键盘和安全区域遮挡。
- 任务卡片：长名称、错误文本、多种状态和三项操作挤在窄列中。可改为名称与状态一行、进度与速度一行、操作独立一行。
- 全部与批量操作：手机上应继续明确区分，取消保留二次确认；固定操作区不能掩盖已选数量或范围。

## 后续实施边界

建议仅修改 NAS 页 CSS 和必要的前端交互，不改官方 AList 登录页、不改后台下载行为。验收需覆盖 320–430px 手机宽度、长文件名、未知大小、大批任务、旋转屏幕、软键盘、浏览器缩放、路径前缀及真实 iOS Safari/Android Chrome。应复用已有浏览器回归，补充真实触控和安全区域验证。
