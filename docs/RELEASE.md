基于 xhofe/alist v3.65.0 的 linux/amd64 镜像，迁入 BitQiu Windows 4.1.0.1 的客户端登录、type=5 新设备短信验证及原文件下载协议。

镜像：ghcr.io/fv4004/alist_bitqiu:latest

也可下载 alist-bitqiu-linux-amd64-image.tar.gz，解压后使用 docker load 导入。

操作说明见仓库 README_BITQIU.md。客户端模式当前提供文件浏览和下载；原网页模式可选。已完成离线协议测试和容器启动检查；未使用真实 BitQiu 账号进行联网验收。网络侧接口或账号权限变化可能需要进一步适配。


本版修复 SMS 流程：新建 BitQiu 存储不要求验证码；先保存并启动 Driver，遇到新设备验证后自动发送首条短信。等待验证正常保存并在存储列表显示状态。收到短信后重新打开编辑页，填写 sms_code 保存即可。重启、重复保存和发送失败不会自动重发；手动 send_sms 保留 60 秒间隔。


v3.65.0-bitqiu.3：为 HTTP 423 等错误显示不含敏感值的接口路径、数字业务码及响应类型。仅当 HTTP 401/403/423 同时携带已知会话失效业务码时执行一次密码重新登录；不根据 423 盲目重试，不自动发短信。新增根目录到多级子目录及下载、423 错误脱敏和有限重登录回归测试。尚未获得实际账号的 423 响应，不能据此宣称所有子目录 423 问题已修复。


v3.65.0-bitqiu.4：修正 Windows 模式将 10401 参数错误一律判为登录过期的行为；增加一次性 diagnose_http 操作，在后台用同一已保存会话对比 Go 与 wget 的真实根目录请求，只显示脱敏摘要，不重新登录或发送短信。诊断结束删除私有临时凭据文件。此版本提供进一步排查能力，尚未确认实际账号 423 的根因。


v3.65.0-bitqiu.5：文件夹优先选用显式 dirId，文件优先选用显式 fileId，并兼容通用 ID。扩展 diagnose_http，分别对比根目录及首个子目录的 Go/wget 请求，报告 ID 字段来源和是否与旧版选取不同，不显示名称、ID 值或凭据。增加多 ID 记录及子目录诊断回归测试。实际账号根目录成功、子目录空响应 HTTP 423 的根因仍需对比结果确认。
